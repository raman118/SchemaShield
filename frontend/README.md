# SchemaShield dashboard

Install with `npm ci`, start with `npm run dev`, and open http://localhost:3000. The backend must be running on port 8000. Configure `NEXT_PUBLIC_API_URL` before starting or building to select the local backend API. Enter the backend's configured bearer token under API connection & authentication and refresh the workspace. The token is held in page memory only; no Next.js proxy injects credentials.

`npm run lint` checks the source. `npm run build` creates the production app. `npm run test:e2e` starts the real FastAPI application with explicitly enabled SQLite test persistence and a Docker-disabled sandbox, then tests analysis, planning, history, audit, authentication, and mobile layout. Install Chromium with `npx playwright install chromium` before browser tests. SQLite browser tests do not establish PostgreSQL persistence or execution acceptance.

The dashboard displays only persisted backend findings and reports. Missing Docker capability disables validation and execution. A passing hash-bound validation report is required for approval; approvals remain subject to server enforcement. Background validation and execution jobs are polled until they finish. No user-controlled execution URL, image, shell command, or host path is accepted.

The locally maintained Button, Card and Radix Tabs components follow the shadcn/ui composition pattern, with `components.json`, class-variance-authority, and merged class utilities. All visible navigation and actions work against backend routes; measurements remain explicitly unavailable until actually collected.

ESLint uses the maintained TypeScript and React Hooks recommended rules directly. The framework's bundled lint preset depended on an unpatched vulnerable glob library at implementation time, so it is deliberately omitted. TypeScript build checks and actual browser navigation tests cover framework behavior.

The build uses Next.js worker threads and the TypeScript compiler API for the pinned TypeScript 5.9 dependency. This preserves full type checking while avoiding operating-system child-process restrictions in managed Windows workspaces. Job polling waits for each response before scheduling another request, and a completed job refreshes only its associated migration. Validation, approval, and execution are disabled while the page is tracking a running job.

`Dockerfile.e2e` pins the official Playwright 1.64.0 Ubuntu Noble image and installs the locked npm dependencies. It runs both the browser workflows and real PostgreSQL runtime test against externally started services; it creates no SQLite fallback and receives no Docker credentials. Run the browser container in the API network namespace when the API and dashboard share ports 8000 and 3000 there. The build context excludes local dependencies, build output, browser reports, screenshots, and environment files.

`npm run format:check` verifies formatting. The default browser suite explicitly skips `tests/runtime.spec.ts`. For full runtime browser acceptance, start the API with real PostgreSQL persistence and an enabled Docker sandbox, then start the dashboard. In PowerShell set `$env:SCHEMASHIELD_E2E_EXTERNAL='1'; $env:SCHEMASHIELD_E2E_RUNTIME='1'` and run `npm run test:e2e -- tests/runtime.spec.ts`. Use `SCHEMASHIELD_E2E_TOKEN` for a customized backend token and `SCHEMASHIELD_E2E_URL` for a customized dashboard URL. External mode prevents Playwright from substituting SQLite or a disabled sandbox. The runtime test verifies the entire concurrent-index validation/approval/execution workflow plus a genuinely interrupted and resumed fixed-fixture backfill, using actual reports and integrity checks. It captures screenshots under `evidence/`.
